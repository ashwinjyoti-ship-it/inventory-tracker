# NCPA Sound Inventory Tracker — Project Context

This is the working context for the NCPA Sound Inventory Tracker — a small,
focused web app that tracks where every sound-equipment item is at all times
across NCPA's venues, replacing untracked manual hand-offs by crew.

## What it does

- **For crew (mobile UI, `/`):** pick your name → check items out (from venue
  → to venue) or return them ("Back to Base" = home venue, or a different
  venue). See your history. Get an alert when items have been out for 5+ days.
- **For admins (`/admin`, password protected):** manage venues, manage crew
  members, see every item's current location and holder, browse the full
  movement log, change the admin password.

## Stack

| Layer       | Choice                                            |
| ----------- | ------------------------------------------------- |
| Frontend    | Vanilla HTML + CSS + JS (no frameworks)           |
| Backend     | Cloudflare Pages Functions (Workers runtime)      |
| Database    | Cloudflare D1 (SQLite at the edge)                |
| Hosting     | Cloudflare Pages — `ls-inventory.pages.dev`  |
| CI / deploy | GitHub Actions, auto-deploy on push to `main`     |

## Data model

- **venues** — id, name, code (e.g. JBT), is_outdoor, active
- **crew** — id, name, role (`member` | `head`), active
- **equipment_models** — id, name (e.g. "SHURE SM 58"), category
- **items** — one row per physical unit (e.g. "SHURE SM 58 #001"). Tracks
  `home_venue_id`, `current_venue_id` (NULL if in transit),
  `current_crew_id` (NULL if at a venue), `destination_venue_id`,
  `last_movement_at`.
- **movements** — append-only log: action (`checkout`|`return`),
  from_venue, to_venue, crew, notes, created_at.
- **settings** — KV: `admin_password_hash` (PBKDF2-SHA256, salted, 100k
  iterations), `token_signing_key` (random 32-byte key for HMAC bearer
  tokens). Both are inserted on first seed only — re-seeding never resets
  the admin password.

## Auth model

- No login for crew — they pick their name from a dropdown (stored in
  localStorage). This is by design: low friction during a show.
- Admin: password-gated. The password lives only as a PBKDF2 hash inside
  D1, never in env vars or in the repo. **Initial password: `Lsi@123456`**
  — change it from the admin UI after first sign-in. Rotating the admin
  password also implicitly rotates by re-saving the hash; bearer tokens
  themselves use a separate signing key.
- Bearer tokens: HMAC-SHA256 over a timestamp, signed by
  `settings.token_signing_key`. 24h TTL. Sent as `Authorization: Bearer ...`.

## CI / deployment

- Trigger: push to `main` (or the active feature branch
  `claude/sound-inventory-tracker-Ipn8S`), or manual `workflow_dispatch`.
- GitHub secrets used: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`,
  `CLOUDFLARE_D1_DATABASE_ID` — all already configured.
- The workflow:
  1. Renders `wrangler.toml` with the real D1 ID.
  2. Reconciles the Cloudflare Pages project so the URL is exactly
     `ls-inventory.pages.dev` (deletes any collision-suffixed siblings,
     creates `inventory-tracker` if missing).
  3. Applies `db/schema.sql` (idempotent).
  4. Seeds `db/seed.sql` only if the items table is empty.
  5. Deploys `public/` + `functions/` to Pages.
- `workflow_dispatch` inputs: `reseed=true` to wipe and re-seed,
  `reset_admin_password=true` (in combination with reseed) to also wipe the
  password back to the seed default.

## Local dev

```sh
npm install
npm run build:seed     # regenerate db/seed.sql from the Excel
npm run dev            # wrangler pages dev (local D1)
```

## Open follow-ups / known limitations

- No item-level QR code scanning yet. Could add: print labels with item IDs,
  scan to add to a checkout/return cart.
- No bulk-import flow for new equipment models — admin adds inventory by
  rebuilding the seed and triggering `workflow_dispatch` with `reseed=true`,
  which loses movement history. Better: an admin "add items" endpoint.
- No per-venue analytics / utilization reports.
- Crew dropdown order is alphabetical with the head listed first; consider a
  pinned-favorites approach if the team grows past ~25.
